# 学业工作流交付矩阵

所有 PASS 均限于合成数据自动化，不等于真实学校验收。

| 模块 | 当前实现 | 尚需核实/限制 |
|---|---|---|
| Student Profile | 本地学生 ID 按 API 地址持久化，恢复时校验档案存在；Demo 与真实组件分开 | 原生重启、不同安装目录隔离待验收 |
| Program / Catalog | 仅当前学生有效绑定、机构/校园一致、精确 Catalog、唯一有效且已确认规则集的非 Mock 候选 | 缺实体/规则不伪造；完整建模向导待补 |
| Course Catalog | 当前学生成功 Review→Apply 的课程，或有可靠修读/课节证据；列出代码、标题、学分、来源时间 | 相似标题不自动等价；跨来源冲突保持人工审核 |
| Course State | 原有幂等应用、快照替换与映射复用保留；无快照真实学生也排除 Mock 修读 | 部分/截断/异常课程历史不能用于确认毕业 |
| Degree Audit | 规则与历史缺失/冲突为 MANUAL_REVIEW_REQUIRED；完成、在修、计划分列；规则来源、Catalog、匹配应用、原因和核实状态可见 | 源码支持的规则树之外仍人工确认；旧审核明确标为历史 |
| Eligibility | 真实课程与目标学期接入已有 PROJECTED 引擎；同学期完成不能充当前置完成证据 | 计划/在修仅条件贡献，不代表学校准许注册 |
| Academic Planner | 复用审核后的节点/课程池与学分身份，真实学期来源过滤、显式 0 学分、排除需审核要求；保存读回与最近两方案比较 | 开课未知提供提示，不保证未来必开或毕业时间 |
| What-if | 已审核绑定方案可创建、保存、读取比较结果，保持关系类型 | 未绑定替代专业与自定义多方案编辑仍待实现 |
| Section Matching | 学生自己的成功应用链、课程/学期/来源身份、取消/漂移等由既有 reviewed-section 校验 | 无 CRN 使用既有可追踪身份，真正歧义仍阻断 |
| Schedule Optimizer | REVIEWED_IMPORTED 模式；选课、时间、地点、读取来源、生成时间、冲突与警告可见 | 座位仅读取时参考；TBA/未知不伪造时间；无注册动作 |
| Apply 刷新 | 成功应用事件使候选与课程状态重新获取，输入/学生/API 变化重置临时结果；迟到请求失效 | 页面导航不自动 Apply；保存的历史方案需显式读取 |

## 身份与学分

课程代码统一使用既有 normalizer（例如 `MATH*1044` → `MATH 1044`），机构/校园/学生/学期/版本继续参与范围判断。Catalog 不覆盖学生历史；原有重复应用及来源冲突回归全部保留。Reviewed rule source-id 经课程定义代码解析，不按相似标题猜测。

Completed 是已修读证据中的实际贡献；In-progress 与 Planned 是潜在贡献；Remaining 与 Requirement Satisfaction 单独核对。等价课程共享学分身份，同一修读/转学/替代记录不会跨排他要求组重复花费；允许 overlap 的节点仍按既有规则处理。未审核等价关系不能为真实档案提供确定性抵扣。零学分是有效数值。

## 合成闭环证据

新增 API 测试实际执行 Review→Apply→候选查询→真实审核保存读回，另测程序冲突降级、恶意/损坏规则 payload、课程星号引用、未 Apply 不可用、学生隔离、重复应用、取消班次、重复/等价/排他组学分。E2E 验证真实 ID 提交、档案恢复、无 Mock 候选、导航零写入和 Apply 后旧响应隔离。此前课程必修/任选、高年级、最低成绩、转学、替代、在修、计划、先修、What-if 和排课的整个既有套件继续运行。

真实 MyProgress、Catalog、Sections、degree audit、eligibility、planner、optimizer 均 **UNVERIFIED**；不得用合成夹具声称验收完成。
